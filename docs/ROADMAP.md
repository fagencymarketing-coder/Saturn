# ДОРОЖНАЯ КАРТА проекта «Сатурн» + как работать с Claude

## Принцип: GitHub = мозг проекта, Tilda = витрина (боевой сайт)
- В GitHub храним ВСЁ, что определяет проект: docs (решения, статус, бренд), прототипы .html, ассеты (лого, иконки), каталог .xlsx, тексты.
- Tilda — где реально живёт сайт для посетителей. Прототипы из GitHub переносим в Tilda руками (блоки/Zero Block/каталог).
- Claude (я) работаю с файлами в GitHub-репозитории; в Tilda залить/нажать «Опубликовать» — только человек.

## Последовательность (правильный порядок!)
1. СТРУКТУРА (прототип, серые блоки) → утвердить. [СДЕЛАНО: V2]
2. ДИЗАЙН (в фирменном стиле) → утвердить. [СДЕЛАНО: тёмная тема + заглушка]
3. КОНТЕНT: тексты (о компании, преимущества, кейсы) + КАТАЛОГ (товары, фото). [В РАБОТЕ]
4. СБОРКА В TILDA: собрать страницы из блоков, вставить контент/каталог.
5. ДОМЕН + ПОЧТА: домен готов (sssaturn.ru); настроить MX для формы.
6. ЗАПУСК: опубликовать, проверить на десктоп/моб.
7. ОПТИМИЗАЦИЯ: аналитика, A/B, SEO (по методике Tilda Education).

Правило: сначала СТРУКТУРА, потом ДИЗАЙН, потом КОНТЕНT. Не наоборот.

## Каталог: когда и что нужно
- Делается на этапе КОНТЕНT (после утверждения структуры).
- Нужно: чистый прайс/номенклатура (Excel), фото товаров, описания/нормы, категории и бренды.
- Tilda: фильтр по 1 признаку — любой тариф; по 2 (категория+бренд) — тариф Business.

## Как переносится на Tilda
- Заглушка/лендинг: блок T123 (HTML) на пустой странице ИЛИ пересбор в Zero Block.
- Каталог: встроенный магазин Tilda (Tilda Store) — категории родные, бренд — теги/характеристики.
- Домен: Настройки сайта → Домен → A-записи на IP Tilda (см. DOMAIN-DNS.md).

## Как работать с Claude (важно!)
- Одна задача за раз, итерациями: показал → утвердил/правки → дальше.
- Присылай скриншоты — я «вижу» их и веду по шагам.
- Все решения фиксируем в docs/ (DECISIONS, STATUS) — это память проекта.
- Утверждай явно («оставляем V2») — тогда не переделываю лишнего.

## Что делать, если у Claude заполнится контекстное окно
- Симптом: новая сессия/«потерял контекст».
- Решение: всё важное лежит в GitHub-репозитории. В новой сессии: подключить репозиторий → я читаю CLAUDE.md + docs/STATUS.md и сразу в теме.
- Поэтому ПОСЛЕ каждого важного шага коммитим изменения в репозиторий (файлы + обновлённый STATUS.md).
- Держи актуальным docs/STATUS.md — это точка восстановления.

## Что коммитить в GitHub
ДА: docs/*, prototype/*.html, assets/ (лого, иконки), catalogs/*.xlsx и тексты, coming-soon/*.
Осторожно: тяжёлые PDF/сканы/видео — через Git LFS (или не хранить в репо, держать в облаке).
НЕ хранить: пароли, доступы к reg.ru/Tilda/почте.
