# Как проверять сайт — три уровня

Полная проверка руками занимает часы и всё равно что-то пропускает.
Поэтому разделено: машина проверяет то, что считается, агент в браузере —
то, что надо нажать, человек — только смысл.

---

## Уровень 1. Машина, локально — 40 секунд

Запускается у меня, до того как что-то уйдёт в Тильду.

```
cd /home/user/saturn
bash tools/render/build.sh                   # собрать главную из блоков
node tools/audit/check.js /tmp/blk/t2.html   # линтер дизайн-системы, 6 ширин
python3 tools/audit/spacing.py               # нечётные отступы
python3 tools/audit/content.py               # содержание и ссылки
```

**`check.js`** на ширинах 1440 · 1280 · 1024 · 768 · 390 · 320 находит:
кегли вне шкалы, лишние насыщенности, радиусы вне системы, отступы не
кратные 4, строки длиннее 90 знаков, зоны нажатия меньше 44px (меряет
настоящую область через `elementFromPoint`, а не рамку элемента),
горизонтальное переполнение, ссылки без доступного имени, число
акцентных плашек на экран.

**`content.py`** сверяет каждый телефон и каждую почту с таблицей в
`docs/SPRAVOCHNIK-SAYT.md`, проверяет ИНН/КПП/ОГРН и открывает все
ссылки: страницы, прайс, сертификаты, протоколы. Любой код кроме 200 —
нарушение. С ключом `--live` проверяет не файлы, а опубликованные
страницы.

**Сверка с макетом:**

```
python3 design/measurements/show.py <секция> <ширина>
```

Замеры утверждённого макета. Если вёрстка расходится с ними — права
вёрстка неправа, а не макет.

## Уровень 2. Агент в браузере — то, что нельзя посчитать

Машина не может нажать кнопку и не видит каталог: он рисуется
скриптом. Это задача агента, по списку:

### Нажать и убедиться, что происходит ровно обещанное

| Что нажать | Что должно произойти |
|---|---|
| «Подобрать решение» | прокрутка к форме заявки |
| «Перейти в каталог» | `/catalog` |
| Каждая карточка товара на главной | страница своего товара, не чужого |
| Чипы «Все · Удобрения · СЗР · Семена» | каталог с нужным разделом |
| «Скачать прайс · PDF» | открывается прайс 2026 |
| «Протокол ↓» в трёх карточках | три **разных** протокола |
| Три карточки документов | сертификат дилера и два СГР |
| «Скачать реквизиты» | карточка предприятия |
| Телефон и почта в шапке, подвале и контактах | набор номера и письмо |
| Форма: отправить пустую | ругается на обязательные поля |
| Форма: отправить заполненную | «Спасибо! Перезвоним в течение рабочего дня» |
| Галочка согласия | ссылки ведут на `/consent` и `/privacy` |
| Каталог: фильтр по культуре | число найденного меняется, товары соответствуют |
| Каталог: поиск «ампир» | находит оба «Ампира» |
| Каталог: «Загрузить ещё» | дозагружает, не дублирует |
| Корзина | **нигде нет** |

### Посмотреть глазами на четырёх ширинах

1440 · 1024 · 768 · 390. На каждой:

- первый экран помещается целиком, прокрутка не нужна, чтобы увидеть
  кнопки и цифры;
- нет горизонтальной прокрутки;
- между секциями нет щелей и наложений;
- ничего не обрезано многоточием там, где это меняет смысл
  (особенно «5 000+ га» и названия FERTIKA в каталоге);
- шапка не перекрывает заголовок секции при переходе по якорю.

### Навести мышь

На каждую ссылку и кнопку. Цвет при наведении должен быть задан:
у Тильды есть глобальное `a:hover{color:#d93800}`, и любая ссылка,
для которой наведение не описано, на нём перекрашивается в оранжевый.
Это самая частая поломка.

## Уровень 3. Человек — только смысл

Машина и агент не отличают правильную цену от неправильной.
Заказчик и я смотрим:

- цифры в блоке результатов — против актов испытаний;
- описания товаров — против `catalogs/tilda-import.csv`;
- тексты страниц — против `docs/TEKST-SAYTA.md`;
- что нигде не всплыли закрытые данные: «Генезис», имена хозяйств,
  «12 лет на рынке».

---

## Порядок перед публикацией

1. Уровень 1 — должен дать ноль нарушений.
2. Выложить на Тильду.
3. Уровень 2 — агент проходит список и присылает отчёт со скриншотами.
4. `python3 tools/audit/content.py --live` — ссылки на живых страницах.
5. Уровень 3 — приёмка.

Если хоть один пункт не пройден, публикация не считается состоявшейся.
