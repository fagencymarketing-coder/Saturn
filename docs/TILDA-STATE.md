## 4. ЗАДАЧА, КОТОРАЯ НЕ ВЫПОЛНЕНА: cookie-баннер

**Почему не сделана.** В настройках проекта Tilda нет пункта «предупреждение об
использовании cookie». Проверены все 18 разделов левого меню (Главное, Домен,
Главная страница, Шапка и подвал, Шрифты, Цвета и стили, Аналитика, SEO, Формы,
Платежные системы, Доставка, Подключаемые модули, Действия, Ограничить доступ,
Экспорт, Сотрудники, Вставка кода, Еще) + поиск по настройкам по запросу
`cookie` → «ничего не найдено».

### Требуемое содержимое баннера

| Параметр | Значение |
|---|---|
| Текст | `Мы используем файлы cookie и Яндекс Метрику, чтобы сайт работал удобнее. Продолжая пользоваться сайтом, вы соглашаетесь с политикой обработки персональных данных.` |
| Ссылка | `/privacy` |
| Текст ссылки (анкор внутри текста) | `политикой обработки персональных данных` |
| Надпись на кнопке | `Хорошо` |
| Положение | внизу экрана |
| Частота показа | один раз (запомнить согласие) |

Страницы `/privacy` пока не существует — ссылку всё равно нужно поставить.

### Варианты реализации (выбрать один)

**Вариант A — штатный блок Tilda (предпочтительно, без кода).**
Библиотека блоков → категория «Другое» → блок с уведомлением об использовании
cookie. Добавить на нужные страницы (или в header/footer-страницу, чтобы
появился на всех), заполнить поля выше в контенте блока, настроить положение
и «показывать один раз» в настройках блока. Стилизовать под палитру из п.2.

**Вариант B — свой код через «Настройки сайта → Вставка кода».**
Вставка в `<body>` / перед `</body>`, применяется ко всему проекту.
Требования к реализации:
- согласие хранить в `localStorage` (например ключ `saturn_cookie_consent`)
  с фоллбэком на cookie; при наличии значения баннер не рендерить;
- баннер `position: fixed; bottom: 0; left: 0; right: 0; z-index: 9999`;
- палитра: фон `#1E1B18`, текст `#FFFFFF`, ссылка и кнопка `#FF4200`,
  hover кнопки `#D93800`, шрифт Montserrat;
- анкор `политикой обработки персональных данных` — ссылка на `/privacy`;
- кнопка «Хорошо» закрывает баннер и пишет согласие;
- адаптив: на мобильных текст в колонку, кнопка на всю ширину;
- доступность: `role="dialog"`, `aria-label`, фокус на кнопке, закрытие по Enter.

### Связанная задача
Страница `/privacy` (политика обработки персональных данных) не создана.
Нужна как минимум страница-заглушка, иначе ссылка в баннере ведёт в 404.
В «Настройки сайта → Еще → Страница ошибки 404» сейчас `Не выбрано`.

## 5. Ограничения и правила работы с проектом

Действуют при любых дальнейших изменениях:

- Менять только то, что явно перечислено в задаче. Ничего больше не трогать.
- Ничего не удалять.
- **Не публиковать** страницы и сайт без отдельного явного разрешения.
- Настройки шрифтов не менять — они выставлены верно (см. п.2).
- Значения вставлять ровно как написано, вместе со знаком `#`.
- Если поле уже заполнено другим значением — заменять на заданное.
- После каждого раздела нажимать «Сохранить изменения» (кнопка глобальная,
  справа вверху, сохраняет весь набор изменений).
- Если раздела или поля нет — пропустить и сообщить об этом, не изобретать
  обходной путь молча.

## 6. Особенности интерфейса Tilda (замеченные при работе)

- Раздел называется **«Главное»**, а не «Основное».
- **«Язык сайта»** лежит в разделе **«Еще»**, а не в «Главном».
- В полях цвета клик открывает поповер-пикер, который перекрывает соседнее
  поле. Закрывается по `Escape`. Значение вводится текстом в hex-инпут.
- Пикер нормализует hex к нижнему регистру при закрытии.
- Цвета в палитру добавляются двумя равнозначными путями: кнопка
  «Управление стилями» → «Добавить цвет», либо плитка «+» прямо в блоке
  «Стили». Форма требует непустое «Название стиля» (по умолчанию
  «Новый стиль») — сейчас в качестве имени проставлен сам hex.
- Поиск по настройкам (левая колонка) ищет только по названиям полей и
  разделов, по-русски; запрос `cookie` ничего не находит.
