## 2. ЗАТЫКИ — требуют действия человека или решения

### 2.1. Email не активированы — заявки НЕ приходят
Оба подключения помечены **«Не активировано»**. Tilda отправила на каждый адрес письмо
со ссылкой подтверждения. Пока по ссылкам не перейдут — формы не будут доставлять заявки.

**Действие:** владельцам ящиков открыть письмо от Tilda и нажать ссылку подтверждения.
Автоматизировать нельзя — нужен доступ к почте. Письма могут попасть в спам,
отправитель `noreply@tilda.ws`.

### 2.2. `/consent` и 404 невозможно проверить визуально
Блок T123 не выполняется в предпросмотре — Tilda пишет прямо в блоке:
«Код будет выполнен на опубликованной странице». Предпросмотр показывает **исходный код**,
а не вёрстку.

Следствие: по `/consent` подтверждено только то, что код сохранён в блоке (3367 символов).
Как он выглядит, переносится ли текст, кликабельна ли ссылка `/privacy` внутри согласия —
**неизвестно до публикации**.

404 на CR16 — нативный блок, он в предпросмотре рендерится нормально, там всё проверено.

**Действие:** либо разрешить публикацию `/consent`, либо принять, что проверка отложена.

### 2.3. Alias `404` занят системой
Tilda отклоняет адрес `404`: `404 - system name. Please set another.`
Поставлен `page404`.

На работу это не влияет — страница подключена через настройку «Страница ошибки 404»,
alias там не используется. Если нужен другой адрес — менять в настройках страницы.

### 2.4. Настройка 404 ругается, что страница не опубликована
Под селектором «Страница ошибки 404» висит красное:
**«Указанная страница не опубликована.»**
Настройка сохранена, но пока страница не опубликована, Tilda будет отдавать свою
дефолтную 404, а не нашу.

**Действие:** опубликовать страницу 404, когда снимут запрет.

### 2.5. `/catalog` не существует
Кнопка «Каталог» на 404 ведёт на `/catalog`. Страницы нет — будет 404 на 404.
Поставлено намеренно, по прямому указанию.

### 2.6. Cookie-баннер так и не сделан
Из предыдущего промта. В настройках проекта Tilda **нет** раздела
«предупреждение об использовании cookie» — проверены все 18 пунктов левого меню
плюс поиск по настройкам (`cookie` → «ничего не найдено»).

Реализуется либо блоком из библиотеки (категория «Другое»), либо своим кодом
через «Вставка кода». Тексты и параметры баннера — в файле
`brief-dlya-claude-code-multitab-prompt.md`, раздел 6.

При этом в политике (п. 7.1) и в тексте согласия баннер уже упомянут как существующий.
То есть юридический текст обещает то, чего на сайте пока нет.

### 2.7. В тексте политики нет гиперссылок
`document.querySelectorAll('.saturn-legal a').length === 0` на опубликованной `/privacy`.
Адреса `https://sssaturn.ru/privacy` и `https://sssaturn.ru/consent` написаны обычным
текстом. В `consent.html` одна ссылка есть (`<a href="/privacy">`).

Если ссылки в политике должны быть кликабельными — правка в исходнике
`files/privacy.html`, не в Tilda.

### 2.8. Главная страница — заглушка
`Blank page`, «Скоро здесь будет новый сайт». Не трогалась. Ссылка «На главную»
с 404 ведёт на неё.

## 4. Техническая шпаргалка по автоматизации Tilda

Собрано на практике, экономит время при следующем заходе.

### Что НЕ работает
- **Клик по координатам из скриншота.** Фрейм скриншота и CSS-пиксели не совпадают
  (виден масштаб 0.98–1.35 в разных состояниях окна). Координаты брать только из
  `getBoundingClientRect()` в том же вызове, либо кликать по `ref` из `find`.
- **`Ctrl+A` через keyboard-эмуляцию** — модификатор теряется, в поле вставляется буква `a`.
  Для очистки поля использовать `triple_click`, либо нативный сеттер value.
- **Ввод текста в Quill-редакторы Tilda** (`.pe-redactor__wrapper.ql-editor`). Поле
  `isContentEditable === false`, `Quill.find()` не находит инстанс, `execCommand` чистит
  но не вставляет. См. ниже рабочий способ.
- **`javascript_tool` на `raw.githubusercontent.com`** — блокируется гардом
  (`BLOCKED: Cookie/query string data`). Читать файл только через `get_page_text`
  или `fetch` из вкладки Tilda.
- **Чтение `location.href` и `a.getAttribute('href')`** в Tilda — тот же гард.
  Обходится разбором: `h.split('?')[0].split('/')`, булевы проверки `h.includes(...)`.

### Что работает
```js
// 1. Точное содержимое файла без транскрипции — fetch из вкладки Tilda (CORS у GitHub открыт)
const src = await (await fetch(RAW_URL, {cache:'no-store'})).text();

// 2. Код в head (страница /projects/editheadcode/) и T123 — редактор ACE
const ed = ace.edit(document.querySelector('.ace_editor'));
ed.setValue(src, -1);
// плюс продублировать в скрытую textarea, Tilda читает её при сохранении
const ta = document.getElementsByName('code')[0];       // T123
// const ta = document.getElementsByName('headcode')[0]; // head
const s = Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype,'value').set;
s.call(ta, src); ['input','change'].forEach(t=>ta.dispatchEvent(new Event(t,{bubbles:true})));

// 3. Открыть панель контента блока
edrec__editRecordContent('<recordid>');   // recordid = id из [id^="record"] без префикса

// 4. Заголовок/описание нативного блока — писать в СКРЫТУЮ textarea, не в ql-editor
function setT(name, v){
  const el = [...document.querySelectorAll('textarea.pe-textarea')].find(e=>e.name===name);
  const s = Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype,'value').set;
  s.call(el, v);
  ['input','change','keyup','blur'].forEach(t=>el.dispatchEvent(new Event(t,{bubbles:true})));
  const w = el.parentElement.querySelector('.ql-editor'); if (w) w.innerHTML = '<p>'+v+'</p>';
}
setT('title', '...'); setT('descr', '...');

// 5. Обычные input (кнопки блока, настройки страницы) — нативный сеттер
function setV(el, v){
  const s = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set;
  s.call(el, v);
  ['input','change','keyup','blur'].forEach(t=>el.dispatchEvent(new Event(t,{bubbles:true})));
}

// 6. Настройки страницы (модалка)
// меню «Еще» в шапке редактора → пункт «Настройки страницы»
// поля: #modalinputtitle, [name=descr], #popup-ps-input-alias
// НЕ вызывать showformEditPageSettings_new() без аргументов — уводит на «Wrong page id!»

// 7. pageid текущей страницы
pageid   // глобальная переменная в редакторе

// 8. Библиотека блоков
[...document.querySelectorAll('.tp-shortcuttools__one-item')]
  .find(e=>/ВСЕ БЛОКИ/i.test(e.textContent)).click();
// категория
[...document.querySelectorAll('.tp-library__type-title')]
  .find(e=>/^Другое$/.test(e.textContent.trim())).click();
// блок — нужны mousedown+mouseup+click с координатами
const t = [...document.querySelectorAll('.tp-library__tpl-body')].find(e=>/T123/.test(e.textContent));
const r = t.getBoundingClientRect();
['mousedown','mouseup','click'].forEach(tp =>
  t.dispatchEvent(new MouseEvent(tp,{bubbles:true,clientX:r.x+r.width/2,clientY:r.y+r.height/2})));
// поиск в библиотеке по коду блока не срабатывает — идти через категории
```

### Подключение сервиса форм
Плитка Email в настройках **не кликается** ничем — ни `ref`, ни координатами,
ни синтетическими событиями, сетевых запросов не порождает. Рабочий путь — прямой URL:
```
https://tilda.ru/projects/forms/add/?type=email&projectid=34592909
```
Поле одно: `[name=appid]`, кнопка «Далее». После отправки — экран
«На указанный e-mail было отправлено письмо…». Для второго адреса — открыть URL заново.

### Прочее
- Расширение периодически отдаёт `Tool "navigate"/"browser_batch" failed in the extension`
  и вкладка «залипает» — навигация перестаёт работать в ней совсем.
  Лечится созданием новой вкладки (`tabs_create_mcp`), старую закрыть.
- Публикация страницы занимает 20–40 секунд, попап «Публикация прошла успешно!»
  появляется с задержкой. Не нажимать повторно.
- Окно браузера физически не сузить до ширины телефона — мешает боковая панель.
  Мобильный оверфлоу проверять замером в DOM: временно задать
  `root.style.width='360px'` и сравнить `scrollWidth`/`clientWidth` у обёртки.
